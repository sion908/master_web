Community Builders の話
-----------------------

特別セッションは、沼口さん（AWS Japan）の「AWS Community Buildersとは？ / CBsに期待していること」。

.. twitter:: 2113572827114897453

コミュニティのプログラムは、Heroes、Community Builders、User Groups、Student Builder Groups があるそうだ。CBは、発信している人を表彰する制度で、支部を運営していることは条件にならない。Twitterでも、ブログでもいい。

.. twitter:: 2113574283230527917

応募は年に一回。ポストを何本したかではなく、どんなポストをしたかが見られる。社内向けではなく、外に出ているものが対象らしい。統計は持っておく。どんな思いで、何を伝えたかったかも残す。そういう話だった。

何もしていなくても出してくる人はいる。内容は正確でも、表現が弱いこともある。誰が見てもわかるものが要る、と聞いた。国別の人数では、日本は3位らしい。

分野は決めて出せ、という話だった。AWSは広い。なんでもできます、は、なんでもできない認定をされる。

.. twitter:: 2113576643063361573

プロフィールの表示名は自由でよい。名前の欄は、アルファベットの本名にしておいた方がいいそうだ。

アカウントの段階の話も出た。カードの要否や、無料、有料、高度な機能という区切りだ。自分は、まだ手順として人に説明できるところまで聞けていない。高度な機能を解除する前までの話だ、と理解している。

直前に Organizations を組んだので、概念が変わったのかと聞いた。本番にするなら Organizations は必要、ということだった。
初心者の入口が簡単になっただけで、普通に開発する上では、あまり変わらなさそう。

.. twitter:: 2113577996011569278

プログラムのページは `AWS Community Builders <https://builder.aws.com/community/community-builders>`_ にある。当日聞いたのは、応募のときに何を見られるか、という側の話だった。


招待セッション
--------------

続いて、課題とWikiを Bedrock に入れて、チャットから質問できる検索の話を聞いた。回答の良し悪しは、まだ感覚で見ているという。

ノイズを落としたい。チャンクの分け方も、データの置き場も、自分で持ちたい。Bedrock Knowledge Bases は、チャンクを分けるかをスイッチで選べる。件名と本文に重みは付けられない。メタデータにも上限がある。取り込みは自前にして、ベクトルの置き場も自分で持つことにしたそうだ。

件名は、本文が長いとベクトルの中に埋もれる。件名を混ぜたインデックスと、タイトルだけのインデックスを別に作り、あとで並べ直す。一つの見方だけでは拾えないものを、別の見方で取りにいく、という話だった。

ノイズの方は、挨拶を消すだけでは済まない。引用を全部消すと、正解が出てこなくなる。消すものを探すより、残すものを決める。重複した引用だけを落とすと、望む回答に寄った。

意味が似ている課題は、意味の検索だけでは分かれない。月だけが違うウェビナーの課題が、その例だった。属性で置き場を分ける。子課題には、親の文脈を一行足す。


自分のLT
--------

自分のタイトルは「AI-DLCをわからないなりにやってみた話」。スライドは `公開している <https://slide.sion908.tech/261023_aws_cbs_fukuoka/index.html>`_ 。

個人で作っているPHPのプロダクトを、IoT Core を中心にした MQTT の構成へ載せ替えることになった。サーバー側は Lambda と DynamoDB と CDK で置き換えて、現地の Raspberry Pi とは IoT Core で双方向に話す。その過程で、せっかくなので AI-DLC を試した。

AI-DLC は、構想からテストまでをAIが進めて、人間は承認する、という建て付けだ。要件とストーリーと、MQTTの境界まで出して、18ステージを一度は越えた気になった。

そこで止まった。サブエージェントに、ファイルを書くツールが渡らない。人間が承認しても監査ログに残らず、次のゲートが開かない。`Kiro の Issue #11150 <https://github.com/kirodotdev/Kiro/issues/11150>`_ が、前者の話だ。フレームワークは捨てて、設計書だけ仕様として残した。

あとは機能を縦に一本ずつ通した。単体のテストは通る。全体を見直したら、認可が抜けていた。状態の保存もなく、再起動で消える。Lambda のハンドラにもなっていなかった。縦に通ったことと、システムとして動くことは、別だった。

狭く切ると、認証は次でやる、結合は後でやる、と先送りされる。テストがデータベースへ直接データを入れていると、入口から出口までの欠落に気づけない。

今は仕様を先に書く。計画と監査は Kiro（Claude）、実装は agy（Gemini）に分けている。同じモデルの見落としを、別の系統に突かせるためだ。

スライド自体は Sphinx で作った。しばらくこのやり方で通してきたが、この日はさすがに限界だと思った。

.. twitter:: 2113583401366388867

後半は長崎の告知にした。JAWS-UG長崎は今年度からリスタートしている。2027年2月27日（土）、グラバー園の旧スチイル記念学校で、リスタート記念のイベントをやる。告知はもう少しあとになる。

懇親会
------

CBであることは、JAWS-UGの支部を運営する条件ではない。参加の条件でもない。これは沼口さんのセッションでも聞いた。懇親会でJAWS-UGの話をしていたら、それでも両方やっている人が多い、という話になった。

その流れで、新しい人を入れるハードルの話が出た。CBになりうる人も、そう多くないんじゃないか、という空気だった。印象に残っている。

長崎を運営している自分にも、同じ種類の悩みがある。せっかく開くなら、もう少し集まってほしい。ただ毎回、会場の都合がある。人が来るかどうかより先に、場所が取れるかでひやひやしている。

とはいえ、参加し続けるには、うちわの安心が要ると思う。そこが難しい。
